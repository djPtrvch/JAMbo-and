# JAMbo-and

Android-порт JAMbo. Основной режим — альбомная ориентация на планшете. Учитывай раскладку и зоны касания на смартфоне, включая Pixel 7.

## Как работать

- Перед работой сообщи пользователю, что проверишь или изменишь. В конце перечисли результат, выполненные проверки, оставшиеся ограничения и самостоятельно принятые решения. Общайся по-русски, надписи приложения оставляй на английском. Временные отметки в отчётах давай по Москве.
- Эталон поведения и интерфейса — ветка `swift` репозитория `djPtrvch/JAMbo`. Сверяй весь затронутый сценарий, включая режимы, жесты, меню и крайние случаи. Любое упрощение или изменение поведения заранее согласуй с пользователем. В Swift-репозиторий ничего не записывай.
- Открывай рабочую сессию только в JAMbo-and. Для сверки возьми конкретный Swift-файл из голого клона. Избегай чтения всего Swift-дерева и больших сводок, если задачу решают целевые исходники.
- Держи звук, модель проекта, музыкальную логику, правки и UNDO в C++. Kotlin и Compose отвечают за интерфейс, касания и Android API. При изменении JNI сверяй обе стороны, включая порядок и размер полей. Сохраняй коды MIDI-целей, совместимость формата проекта и поведение уже сохранённых проектов.
- В `onAudioReady` и вызываемом им коде исключены выделение и освобождение памяти, блокировки, JNI, логирование и системные вызовы кроме часов. Снимки собираются вне колбэка. При порте DSP сохраняй типы, константы и порядок операций Swift, избегай `-ffast-math`.
- Вноси небольшие правки по теме задачи. Согласуй переход к новой функции или этапу. Комментарии и документы — по-русски, Composable — короткие, ориентир для файлов — около 400 строк. При исправлении регрессии проверяй обычный сценарий и точный жест или последовательность, которые привели к сбою. Различай тесты Core, проверку Compose и прогон конкретного APK на устройстве.
- Коммиты делай небольшими и тематическими, без идентификаторов моделей. Перед изменением дополнительных документов согласуй с пользователем путь и содержание, если он уже явно не запросил эту правку.

## Команды

Из корня репозитория, для тестов Core на Linux нужны CMake ≥ 3.22 и C++17.

```bash
scripts/fetch-test-deps.sh
cmake -S tests -B build/tests -DCMAKE_BUILD_TYPE=Release
cmake --build build/tests -j 4
build/tests/core_tests
```

Эталон Swift читай выборочно.

```bash
scripts/fetch-swift-src.sh
git -C third_party/jambo-swift.git ls-tree -r --name-only swift ios/JAMbo.swiftpm/UI
git -C third_party/jambo-swift.git show swift:ios/JAMbo.swiftpm/UI/ArrangeWindow.swift
```

Android APK штатно собирает [GitHub Actions](.github/workflows/android.yml). Команды раннера — `scripts/fetch-deps.sh` и `gradle --no-daemon assembleDebug`. JDK 17, Gradle 8.11.1, SDK 35, NDK 27.2.12479018, ABI `arm64-v8a`. Gradle Wrapper отсутствует. Жди результаты CI при правках C++, тестов, скриптов или workflow. Для малых правок интерфейса и документации ожидание CI не требуется. При запросе на обновление APK проверь публикацию рабочего коммита и версию перед выдачей ссылки. Подробности о подписи и задачах CI — [build-ci.md](docs/ai/build-ci.md).
